# v1.2.1 范围与验证记录

2026年10月14日。在 v1.2.0 关键帧 / mockup 交付基础上增加 Sound & Music Execution：Music Mode Confirmation Gate、Music-Aware Editing、Audio Treatment 与抽象音频 MCP capability。正式 timeline schema 与 Structure CSV 表头保持不变。

## 本版实际改动

- 新项目模板默认启用 `music_direction_policy=mode_confirmation_required`，使用 `music-direction.json` 记录 Director 2 推荐与确认状态。
- `narrative_led / hybrid / music_led` 进入 D2 决策；已有明确用户选择直接承接，仅 Director 推断时停在 `proposed` 等待明确回复。
- 新增可选 `music-map.json`，用于 BPM / beat / accent / energy / section candidates 与编辑意义上的 Music Map / AV Mapping。
- Execution Plan 增加 Audio Treatment Plan；支持 preserve / isolate / attenuate / replace / remove / designed silence，执行说明覆盖 gain / fade / duck / mix / normalize 与按需 dialogue separation。
- MCP 适配新增 `extract_audio / separate_dialogue / analyze_music / mix_audio / inspect_audio` 抽象能力；具体后端不写死。
- `music-direction.json` 与采用 Music Map 进入 Direct 2 授权指纹；确认后改动使旧授权失效。
- 旧项目未声明 `music_direction_policy` 时保持原机械行为。

## 未由本轮自动化证明的内容

本版没有随包安装 Demucs、具体音乐分析库或某个具体音频 MCP，也没有用真实影视素材验证人声分离、音乐分析、混音听感或 WorkBuddy 的具体 MCP 配置。`separate_dialogue` 等只是抽象 capability；实际环境必须完成 capability discovery、短样本测试与核听。Music Map 的编辑意义、卡点审美、分离伪影、对白清晰度、最终 loudness 与手机听感仍需真实媒体 QA，不能由 196 项工程回归替代。
