# v1.2.1 范围与验证记录

2026年10月17日。以用户本轮提供的 v1.2.0 安装包为底稿，针对项目实测返工点做“减法式加固”，不增加创作阶段。

## 本版范围

1. **Scope Lock** 不再做独立状态文件；只在既有 Narrative Direction、Detail handoff、Execution Plan 中承接“当前阶段 / 可修改 / 不可修改 / 已否决”四项。
2. **Detail STOP**：目标问题、最小完整互动 / 动作单元、Edit Boundary、相关反证四项闭合后停止继续加密读取。
3. **Visual Reproducibility Gate**：Aesthetic Mockup 负责选审美；Executable Proof 必须由最终 Execute 可访问的同一实际工具链生成。两步允许跨模型 / 会话完成；`capability-map.json` 继续作为工具映射来源。
4. 新项目只增加 `visual_gate_status`、`visual_mockup_ref`、`visual_proof_ref` 三个 project 字段；不新增 current-state、visual-style、toolchain 或 music gate 文件。

## 机械门槛

- 新 Visual Gate 字段存在时，`ready_for_render` 只接受 `proof_confirmed` / `not_applicable`。
- `proof_confirmed` 必须有两个独立的真实文件：selected mockup 与 executable proof；两者都要进入 `execution_reference_asset_refs`。
- mockup / proof 内容改变继续触发现有 reference-asset 指纹失效。
- 旧项目没有 Visual Gate 字段时保持 v1.2.0 的 warning-only 兼容行为。

## 验证边界

- 自动化能证明 Gate 状态、文件存在性、旧项目兼容和现有指纹失效；不能证明 proof 的审美质量。
- 自动化不读取图片生成历史，因此不能独立证明某张 proof 确实由声明的 renderer 生成。Toolchain Continuity 仍须由 `capability-map.json`、execution-handoff、execution-reference 与人工确认共同保证。
- 本轮没有用真实长视频完整跑一遍 “Aesthetic Mockup → Executable Proof → 最终成片” 视觉对照。

文件级改动见同名 JSON。
